## The `REGEXP` operator, without the setup

SwiftQL has rendered `X REGEXP Y` since v1.4.2, but SQLite ships no `regexp`
function, so the statement failed to prepare unless the application registered
one first. This release supplies that function. `Where(person.name.regexp("^A"))`
now prepares and runs on a plain connection, and the rendered SQL is unchanged.

The bundled implementation is backed by Swift `Regex`, so the pattern syntax is
Swift's. A pattern is searched for anywhere in the subject, which is what the
widely used `regexp` extensions for SQLite and PostgreSQL's `~` operator do;
anchor with `^` and `$` for a whole-subject match. Each pattern is compiled once
per statement execution rather than once per row, so a scan pays one compile and
then only matches. `REGEXP` also works on the two paths that carry no live
registration: a static query descriptor records the signature of the function it
needs, and the SwiftPM build validator registers the same implementation on its
snapshot connection.

A pattern no longer has to be a string. `XLRegexPattern` matches a `Regex`
written with `RegexBuilder`, so it can be composed from named pieces and checked
by the compiler:

```swift
import RegexBuilder
import SwiftQL

enum PersonPatterns {
    static let leadingA = XLRegexPattern {
        Anchor.startOfSubject
        "A"
        ZeroOrMore(.any)
        "n"
        Anchor.endOfSubject
    }
}

let query = sql { schema in
    let person = schema.table(Person.self)
    Select(person)
    From(person)
    Where(person.name.regexp(PersonPatterns.leadingA))
}
```

**Upgrade impact.** The release is additive, and there are no deprecations,
platform changes, or compiler-requirement changes. An application that already
registers its own two-argument `regexp` keeps it: SwiftQL never replaces a
`regexp` that is already on the connection, matched on the name and on either
the exact argument count or the `-1` SQLite reports for a variadic function. An
application that relied on the operator failing is the only code this changes.
Two rules come with `XLRegexPattern`: the registry does not keep the pattern
alive, so hold it in a `static let` or a property for as long as statements
using it can execute, and a statement matching an `XLRegexPattern` cannot become
a static query descriptor, because a key names a registration in one process —
use a pattern string when a statement is validated at build time.
